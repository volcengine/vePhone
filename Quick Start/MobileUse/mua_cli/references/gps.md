# GPS 定位注入参考

云手机本身没有 GPS 硬件，`GpsInfo` 参数用于在任务启动前向云手机注入虚拟定位，让地图类 App 显示指定位置。

`geo.py` 把 GPS 获取抽象为**统一接口 + 多来源降级链**：无论位置来自系统定位、IP、图片、文本还是用户输入，上层业务只调一个 `acquire_gps()`，无需关心来源。

## 获取方式总览

| 优先级 | 方式 | 来源标识 | 精度 | 需要权限 | 依赖 |
|---|---|---|---|---|---|
| 1 | 文本坐标解析（提示词中含坐标） | `parse` | ±5m | 否 | 无 |
| 2 | 图片 EXIF 元数据（提示词指向带 GPS 的图片） | `exif` | ±50m | 否 | `Pillow` |
| 3 | macOS 系统定位（CoreLocation） | `system` | 米级（含海拔/速度/方位角） | **是** | `pyobjc-framework-CoreLocation` + 终端定位权限 |
| 4 | IP 定位（ip-api.com → ipinfo.io → ipapi.co） | `ip` | 城市级（±10km） | 否 | 无 |
| 5 | 地理编码（地址/地名/城市 → 坐标） | `geocode` | 街道级（±2km） | 否 | 无（在线服务） |
| 6 | 手动输入（坐标或地址） | `manual` | 取决于输入 | 否 | 交互终端 |

**坐标系**: 全部使用 WGS-84（火山引擎要求），刻意避开国内地图服务的 GCJ-02/BD-09 偏移坐标系。

## 降级链工作方式

`acquire_gps()` 按上表顺序依次尝试，**第一个成功的来源**即为结果，失败自动降级到下一个：

```
用户描述任务
   │
   ▼
┌─ parse  提示词里直接含坐标? ────────── 是 → 直接用 (零成本, 高精度)
│  否
├─ exif   提示词指向含 GPS 的图片? ────── 是 → 解析 EXIF
│  否
├─ system 用户允许 + 系统定位可用? ────── 是 → CoreLocation (米级)
│  否
├─ ip     IP 定位成功? ────────────────── 是 → 城市级
│  否
├─ geocode 提示词含地名/地址? ─────────── 是 → 地理编码
│  否
└─ manual 交互询问: 手动输入坐标或地址 ── 用户输入 → 完成
```

关键设计：
- **权限分离**：`parse/exif/geocode/manual` 使用用户主动提供的信息（提示词/输入），**不需要系统权限**；只有 `system` 需要授权。用户拒绝自动获取时，仍可用提示词里的坐标/地名，或手动输入。
- **错误不中断**：单个来源抛异常（网络超时、依赖缺失、解析失败）只打印一行说明，继续降级。

## 每种方式详解

### 1. 文本坐标解析（parse）

**适用场景**：提示词里直接带了坐标，如"定位到 39.916527,116.397128"。

**支持格式**（自动识别，无需区分经纬度顺序）：
```
39.916527,116.397128       十进制, 纬度在前 (常见)
116.397128, 39.916527      经度在前也能识别 (超范围自动判断)
39.916527 116.397128       空格/中文逗号分隔均可
39°54'26"N 116°23'29"E     度分秒 (DMS)
39°54′26.5″N 116°23′29.2″E 度分秒含小数
```
无效输入（如"上海市"、单个数字、超范围值）不会误判。

### 2. 图片 EXIF 元数据（exif）

**适用场景**：提示词指向一张手机/相机拍摄的照片（照片 EXIF 常含拍摄地 GPS）。

**依赖**：`Pillow`（requirements.txt 已包含；不装则跳过此来源）。

**用法**：把图片路径写进提示词即可：
```
你：这张照片是在哪里拍的？/tmp/trip/photo1.jpg 把位置注入云手机
```
> ⚠️ 只有原图含 GPS 标签才有效；微信等社交软件压缩/转发后的图片通常已抹掉 EXIF。

### 3. macOS 系统定位（system）

**适用场景**：需要精确位置的场景（导航、精确打卡），本机在 macOS 上运行。

**依赖**：`pyobjc-framework-CoreLocation`（requirements.txt 已包含，仅 macOS 安装）+ 终端定位权限。

**授权方式**：首次运行触发系统授权弹窗；也可手动开启：
`系统设置 → 隐私与安全性 → 定位服务 → 终端（或你的终端 App）`

未授权时自动降级为 IP 城市级定位，功能不受影响。

### 4. IP 定位（ip）

**适用场景**：城市级定位（"附近有什么好吃的"），无需任何权限和配置，自动兜底。

**工作方式**：依次尝试 ip-api.com → ipinfo.io → ipapi.co 三个免费服务，全部失败才降级。

**注意**：IP 定位返回的是**出口网络所在城市**，VPN/代理会让结果偏移；精度约 ±10km。

### 5. 地理编码（geocode）

**适用场景**：提示词含地址/地名/城市（"导航到上海虹桥站"、"去西湖"），需要转成坐标。

**工作方式**：调用 [Nominatim](https://nominatim.openstreetmap.org/)（OpenStreetMap 的免费地理编码服务，无需 key），把地名解析为 WGS-84 坐标。

**可替换**：国内生产环境可换成高德/腾讯地理编码（需自行申请 key），注意其返回 GCJ-02 坐标系，需转换回 WGS-84 再注入。

### 6. 手动输入（manual）

**适用场景**：自动获取全部失败，或用户拒绝自动获取但仍想注入位置。

**交互示例**：
```
[定位] 自动获取未成功。可手动输入位置 (直接回车跳过):
  坐标或地址 (如 39.916527,116.397128 或 上海市) [q=退出]: 上海市
[定位] 已获取: 上海市, 中国, 北纬 31.230416, 东经 121.473701 (来源: 地理编码 (Nominatim), 精度 ±2000m)
```
支持输入坐标（直接使用）或地址（自动地理编码），最多重试 3 次，输入 `q` 或空回车退出。

## 权限与隐私

每次发起任务前都会**询问用户是否允许获取位置**：
- 允许 → 走完整降级链（含系统定位/IP），并**告知结果**（来源/坐标/精度）
- 拒绝 → **不使用系统定位和 IP 定位**（隐私来源），仅尝试提示词中的坐标/地名，或让用户手动输入

```
--- GPS 定位注入 ---
[提示] 任务涉及位置, 可注入本机定位到云手机
是否允许获取当前位置并注入云手机 GPS? [y/N]: y
[定位] 已获取: 中国 上海市 上海, 北纬 31.222200, 东经 121.458100 (来源: IP 定位, 城市级)
[定位] GpsInfo 注入值: "121.458100,31.222200,0,0.0,0,10000"
```

## GpsInfo 格式

```
"经度,纬度,海拔,速度,方位角,定位精度"   (英文逗号分隔)
示例: "116.397128,39.916527,50,0,0,10"
     经度 116.397128, 纬度 39.916527, 海拔 50m, 速度 0m/s, 方位角 0°, 精度 ±10m
```

## 编程式获取

```python
from geo import acquire_gps, ask_location_permission

prompt = "帮我看看附近有什么好吃的"
if ask_location_permission(prompt):          # 智能询问: 位置相关才问
    gps_info = acquire_gps(prompt=prompt)    # 完整降级链, 自动降级到手动输入
else:
    gps_info = acquire_gps(prompt=prompt,
                           allow_permission=False,   # 不用系统定位
                           allow_ip=False)           # 不用 IP 定位
# 例: "121.458100,31.222200,0,0.0,0,10000"
```

参数说明（`acquire_gps`）：
| 参数 | 默认 | 说明 |
|---|---|---|
| `prompt` | `""` | 用户提示词，供文本坐标/图片路径/地名提取 |
| `allow_permission` | `True` | 是否允许系统定位（用户同意后传 True） |
| `allow_ip` | `True` | 是否允许 IP 定位（拒绝自动获取时传 False） |
| `allow_manual` | `True` | 全链失败后是否询问手动输入（非交互场景传 False） |
| `timeout` | `15.0` | 系统定位超时（秒） |

## 扩展：接入更多定位来源

`geo.py` 内置 6 个来源，若要接入**基站定位 / 网络定位 / GPS 硬件设备**（串口/蓝牙接收器）等，只需继承 `GpsSource` 并注册，上层代码零改动：

```python
# 示例: 接入自定义 GPS 设备 (伪代码)
from geo import GpsSource, GpsContext, LocationInfo, register_source
from typing import Optional

@register_source
class SerialGpsSource(GpsSource):
    name = "serial_gps"              # 唯一标识
    label = "串口 GPS 设备"
    requires_permission = False      # 按需
    priority = 25                    # 插入降级链位置 (如 system 之前)

    def acquire(self, ctx: GpsContext) -> Optional[LocationInfo]:
        # 读取串口 NMEA 报文 ($GPGGA), 解析经纬度...
        return LocationInfo(
            latitude=31.2304, longitude=121.4737,
            accuracy=3.0, source="串口 GPS 设备",
        )
```

注册后自动进入降级链，`acquire_gps()` 会按 `priority` 顺序尝试。`priority` 越小越优先（内置来源：parse=10, exif=20, system=30, ip=40, geocode=50, manual=90）。

## 误差权衡

- 文本坐标 / 系统定位：米级，适合导航、精确打卡
- EXIF：照片拍摄地，适合"照片在哪里拍的"场景
- 地理编码：街道级，适合"导航去某地址"
- IP 定位：±10km 城市级，适合"附近美食/景点"
- 同一位置重复注入不消耗配额，GpsInfo 是任务启动时的静态参数
